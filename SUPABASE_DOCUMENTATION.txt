3. ESTRUCTURA DE LA TABLA: survey_responses
================================================================================

Tabla: public.survey_responses

Columnas:
--------
• id                  → UUID (clave primaria, auto-generado)
• color              → INTEGER (1-5, evaluación del color)
• aroma              → INTEGER (1-5, evaluación del aroma)
• sabor              → INTEGER (1-5, evaluación del sabor)
• textura            → INTEGER (1-5, evaluación de textura)
• nivel_salado       → INTEGER (1-5, evaluación del nivel de sal)
• sabor_garbanzo     → INTEGER (1-5, evaluación del sabor a garbanzo)
• aceptacion_global  → INTEGER (1-5, evaluación general del producto)
• consumiria_nuevamente → BOOLEAN (¿consumiría el producto nuevamente?)
• created_at         → TIMESTAMP (timestamp automático UTC)

Restricciones:
- Todas las evaluaciones (1-5) tienen validación CHECK
- Timestamp automático con zona UTC
- ID es generado automáticamente con gen_random_uuid()


4. POLITICAS DE SEGURIDAD (Row Level Security - RLS)
================================================================================

Estado RLS:          HABILITADO
Propósito:           Permitir acceso público (anónimo) controlado

Política 1: "Permitir inserts anónimos"
- Tipo:              INSERT
- Usuarios:          Cualquier usuario anónimo
- Condición:         Siempre verdadero (permiso universal)
- Uso:               Permite que usuarios anónimos envíen respuestas de encuesta

Política 2: "Permitir select público"
- Tipo:              SELECT
- Usuarios:          Cualquier usuario anónimo
- Condición:         Siempre verdadero (permiso universal)
- Uso:               Permite que usuarios anónimos lean resultados en el dashboard
